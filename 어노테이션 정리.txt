[ 1. Lombok (롬복) 라이브러리 ]
DTO나 컨트롤러 작성 시 반복되는 코드를 획기적으로 줄여주는 도구입니다.

* @Getter: 클래스 내 모든 필드에 대한 Getter 메서드를 자동으로 생성해 줍니다.
* @Setter: 클래스 내 모든 필드에 대한 Setter 메서드를 자동으로 생성해 줍니다.
* @ToString: 클래스 내 모든 필드의 값을 문자열로 출력해 주는 toString() 메서드를 자동으로 생성해 줍니다.
* @RequiredArgsConstructor: 클래스 내에 'final' 키워드가 붙은 필드들을 모아 자동으로 생성자를 만들어 줍니다. 최근 스프링에서 가장 권장하는 '생성자 의존성 주입'을 위해 주로 사용합니다.


[ 2. Spring Framework (스프링 코어 및 MVC) ]
스프링 컨테이너가 객체를 관리(Bean)하고, 웹 브라우저의 요청을 처리하기 위한 핵심 어노테이션들입니다.

* @Component: 스프링이 직접 객체를 생성하고 관리하도록 '스프링 빈(Bean)'으로 등록하는 가장 기본적이고 포괄적인 어노테이션입니다.
* @Controller: 스프링 빈으로 등록함과 동시에, 웹 브라우저의 요청(Request)을 받아 처리하고 화면(View)을 반환하는 컨트롤러 역할을 부여합니다.
* @Service: 스프링 빈으로 등록함과 동시에, 핵심 비즈니스 로직(업무)을 처리하는 서비스 계층의 역할을 부여합니다.
* @Repository: 스프링 빈으로 등록함과 동시에, 데이터베이스에 접근하여 데이터를 주고받는 DAO 계층의 역할을 부여합니다.
* @Autowired: 객체 내부에서 다른 객체가 필요할 때, 직접 new로 생성하지 않고 스프링 컨테이너가 미리 만들어둔 객체를 찾아 자동으로 주입(의존성 주입, DI)해 줍니다.
* @RequestMapping: 특정 URL 주소로 요청이 들어왔을 때, 이를 어떤 클래스나 메서드가 처리할지 매핑(연결)해 줍니다. (메서드 방식 지정 가능)
* @GetMapping: @RequestMapping 중에서도 HTTP 'GET' 방식의 요청만 전문적으로 받아 처리합니다. (주로 페이지 이동, 데이터 조회 시 사용)
* @PostMapping: @RequestMapping 중에서도 HTTP 'POST' 방식의 요청만 전문적으로 받아 처리합니다. (주로 폼 데이터 전송, 데이터 추가 시 사용)
* @RequestParam: 클라이언트가 보낸 파라미터(데이터)를 메서드의 매개변수 변수에 1:1로 쏙쏙 담아줍니다. (defaultValue 속성으로 초깃값 설정 가능)
* @ModelAttribute: 파라미터를 수집함과 동시에 별도의 처리 없이 즉시 Model 객체에 담아 JSP 화면으로 넘겨주는 과정을 단일화합니다.
* @ResponseBody: 컨트롤러가 반환하는 데이터를 ViewResolver(JSP 화면)로 보내지 않고, 객체 자체를 JSON 형식 등으로 변환하여 클라이언트에게 데이터로 직접 응답합니다.
* @RequestHeader: 클라이언트의 요청 헤더(Header) 정보(예: User-Agent 등 브라우저 정보)를 메서드의 매개변수로 곧바로 수집해 줍니다.


[ 3. JUnit & Spring Test (단위 테스트) ]
톰캣 서버를 켜지 않고도 자바 코드와 DB 로직을 빠르게 테스트하기 위한 어노테이션들입니다.

* @RunWith: JUnit 테스트를 실행할 때, 순수 자바 환경이 아니라 스프링의 테스트 환경(SpringJUnit4ClassRunner) 위에서 구동되도록 지시합니다.
* @ContextConfiguration: 테스트를 진행할 때 스프링 컨테이너가 어떤 설정 파일(XML)을 읽어서 빈(Bean)을 준비해야 하는지 경로를 지정합니다.
* @Test: 이 어노테이션이 붙은 메서드를 독립적으로 실행 가능한 하나의 테스트 케이스로 인식하게 합니다.
* @Ignore: 작성된 테스트 메서드 중에서 당장 실행하고 싶지 않은 메서드를 테스트 대상에서 임시로 제외(무시)시킵니다.
